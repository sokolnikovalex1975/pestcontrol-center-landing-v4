## Тестовая версия

Ветка `gh-pages` публикуется на GitHub Pages. В тестовой версии нет счётчиков UIS и Яндекс Метрики и скрипта Radist (ссылка Telegram — с готовым текстом, но без кода заявки), а форма работает в демо-режиме: показывает «Заявка отправлена», но никуда не передаёт данные. Демо-режим включается только на домене `github.io`.

## Выкладка на хостинг

Сайт размещён на виртуальном хостинге Timeweb, каталог `public_html`.

1. Загрузите файлы из корня ветки `main` (кроме `README.md`, `CHANGES.md` и `tools/`). Переименуйте при загрузке:
   - `index.html` → `index.php`, вставив перед `</body>` блок из `server/counters.html`;
   - `privacy/index.html` → `privacy/index.php`;
   - `soglasie/index.html` → `soglasie/index.php`.
2. Из папки `server/` загрузите в корень сайта `.htaccess`, `robots.txt` и `sitemap.xml`.
3. Не перезаписывайте `send.php` на сервере: только там указаны пароль почты и основной адрес, на который приходят заявки. В репозитории вместо них заглушки. Если меняете обработчик, перенесите эти две строки из серверной версии. Копия каждой заявки уходит также на b2b@pestcontrol-center.ru (`$toEmailB2b`, с 22.10.2026).
   **Для v4 обязательно** перенесите в серверный `send.php` две правки из репозитория:
   - в список `$allowedTypes` — строку `'Фармацевтическое производство',`, иначе заявки с этим типом объекта сервер отклонит с ошибкой «Выберите тип объекта»;
   - `$consentVersion = '22.10.2026';` — в письме с заявкой должна стоять действующая редакция согласия (сменился оператор персональных данных).
4. PHPMailer 7.1 установлен на сервере в `vendor/` через Composer (`server/composer.json`) и в репозиторий не входит.
5. Изображения v4 загружаются под новыми именами: `ind-bakery.webp`, `ind-kitchen.webp`, `ind-hotel-room.webp`, `ind-pharma.webp`, `p-pigeon.webp`, `p-bedbug-macro.webp`, `p-moth.webp`. Сервер кэширует картинки на год, поэтому файл с прежним именем и новым содержимым посетители увидели бы не сразу. Старые файлы больше не используются, их можно удалить: `ind-elevator.webp`, `ind-food.webp`, `ind-horeca.webp`, `ind-hotel.webp`, `p-bird.webp`, `p-bedbug.webp`, `p-stored.webp`. В `server/sitemap.xml` поставьте дату выкладки в `lastmod`.
6. Статические файлы сервер кэширует на год. После изменения `style.css`, `app.js` или `legal.css` поменяйте параметр `?v=` в ссылках на них, запустите `python3 tools/build.py`, иначе посетители получат старую версию.
7. Перед выкладкой главной запустите `python3 tools/build.py` и загрузите `index.html` (как `index.php` со счётчиками), `app.min.js` и новые файлы из `fonts/` и `img/`. Счётчики UIS и Метрики вставляются в собранный `index.html`.
8. Выкладки 28.10 и 29.10.2026 сделаны скриптом `tools/deploy/run_all.sh` по FTP из «Терминала» на Mac: копия заменяемых файлов, сверка с проверенной версией, загрузка, обратная сверка по SHA-256, откат при ошибке. Из облачной среды Perplexity FTP сейчас недоступен. Для новой выкладки списки файлов и ожидаемые суммы задаются в `deploy.conf` рядом со скриптом.
9. Пакет для выкладки собирает `python3 tools/deploy/make_pkg.py --out ../release` (папка вне репозитория): `pkg/` с `index.php` главной и страницы договора (счётчики вставлены), `style.css`, `sitemap.xml`, а также `MANIFEST.sha256`, `deploy.conf` (суммы текущих файлов сайта для сверки) и копию `run_all.sh`. Пакет не собирается, если на странице остались жёлтые пометки или `noindex`. При откате `run_all.sh rollback` возвращает заменённые файлы; папку новой страницы на сервере при необходимости удалить вручную.
10. После правки `server/counters.html` проверьте ожидание подмены номера и коды Radist: `CHROME=/путь/к/chrome node tools/qa/tel_wait_test.mjs` и `CHROME=/путь/к/chrome node tools/qa/radist_test.mjs` (нужен `puppeteer-core`).
11. После правки шрифтов или первого экрана проверьте сдвиг макета: `CHROME=/путь/к/chrome node tools/qa/hero_cls_test.mjs` (постепенная загрузка) и `CHROME=/путь/к/chrome node tools/qa/font_cls_test.mjs` (подмена запасного шрифта на Inter). Метрики запасного шрифта «Inter Fallback» в `style.css` рассчитаны под Inter 4 из `fonts/`: при замене файлов Inter их нужно пересчитать.

## Документы

Тексты политики и согласия собираются скриптом `python3 tools/legal/build_legal.py`. Оператор персональных данных — ООО «Центр дезинфекционных услуг» (ИНН 7714462211, КПП 771401001, ОГРН 1207700257775) — указан одной строкой внизу каждой страницы; реквизиты и контактная почта задаются в начале скрипта.
